## 1. 范围与交付物

本阶段把数据库从“只认识首次安装版本”升级为可执行后续迁移的机制，并以站点元信息作为第一个真实升级用例。用户可以在后台设置描述、语言和分享图片，公开页面从已发布快照输出自己的站点身份，不再继承原站 canonical 或分享图。

保留当前 Node.js >=24、PostgreSQL 18、单站点、单管理员和现有安装/认证/发布/资源保护。不更换框架，不重写 3D 引擎，不改变 Logo、黑洞和场景参数。不在本阶段实施长缓存、发布产物库、完整静态降级页或后台全量模块拆分。

## 2. 当前问题与相关边界

- `admin-server/migrations.js` 只加载 `001-initial.sql`，检查固定版本 1 和一个结构签名。
- `installation.js` 的轻量运行时状态检查也只接受版本 1；数据库不可用必须继续失败关闭。
- `scripts/db-migrate.js` 目前能校验已有安装，但没有第二个升级步骤。
- `site_settings.site` 和 `templates.schema_config.site` 使用 JSONB；`validateConfig` 校验精确字段集合，不能只在管理端添加字段。
- 发布快照为 format 2，历史版本不可变；历史配置恢复为草稿时须兼容新字段。
- `index.html` 中 canonical/OG/Twitter 有原站地址；服务端和旧引擎分别更新部分标题，需要统一元信息来源并测试导航后的结果。
- `collectReferences` 按明确资源字段收集授权引用，新的分享图必须纳入这条链路，不能只在 HTML 中拼一个未授权资源 ID。

## 3. 数据库迁移契约

### 3.1 迁移注册与检查

- 引入受源码控制的迁移注册表，按正整数连续版本列出 SQL 文件、校验和与预期结构签名；不接受数据库或请求传入任意 SQL/路径。
- 保持 `001-initial.sql` 内容和已公布的校验和不变。已有 schema 1 仍按原来的真实结构检查，不能仅凭版本号就视为可信。
- 已执行迁移必须是已知列表的完整前缀，逐项校验版本和 checksum。缺号、未知未来版本、旧迁移被改写、结构不一致均标记不兼容。
- 若 002 只变换 JSONB 数据而没有 DDL，schema 1/2 可以具有相同结构签名；版本由可信迁移记录识别，数据契约另行验证，不能把结构指纹当作内容校验。
- 完整 schema fingerprint 检查发生在预检/显式升级，不扩展为每个媒体请求都扫描 PostgreSQL 系统目录。
- 运行时轻量检查接受当前所需版本；已安装但落后于当前版本的库显示“需要升级”，不给业务 API 放行，也不开放首次安装。
- 安装相关写入只允许明确的 `uninstalled` 状态，不能继续使用“排除几个已知状态后默认放行”的判断；新状态 `upgrade_required` 返回维护响应并被安装 UI 明确识别。
- 保留原 PostgreSQL 18 版本边界，本次不扩大到其他主版本。

### 3.2 首次安装

- 真正的新库执行完整迁移链到 schema 2，再导入当前格式内容、创建管理员并写安装完成标记；仍在同一安装事务和现有 advisory lock 中提交。
- 空白、内容包和旧 SQLite 只读导入三条路径都生成包含新站点字段的草稿/schema_config。
- 迁移先于导入执行，因此不能仅靠 002 的数据回填处理新安装；导入契约和空白配置构造器都必须主动产生最新字段，不能把 language 统一清空。
- 已知的未完成 schema 与未知残留分别校验，不能把查询失败或结构异常当作“可重新安装”。
- 首次安装仍不要求媒体、运行包或 S3 必须完整；相关缺失状态与现有策略一致。

### 3.3 已安装实例升级

- 通过显式 `npm run db:migrate` 进入升级，不在服务器启动、HTTP 请求或管理员登录时自动迁移。
- 在事务级安装/升级互斥锁内重新检查当前结构、迁移记录和已安装标记，只执行尚未应用的迁移。
- SQL、迁移记录、installation.schema_version 与必要草稿数据变换在同一事务提交；失败完整回滚本次变更，重复运行不重复变换。
- 不修改管理员密码、账号、资源 ID、云凭证、作品 ID、发布指针和历史版本内容；installation 的原始 source、completed_at 保留。
- CLI 区分无需升级、成功升级、需先安装、不兼容与连接失败；输出不能包含密码或完整连接串。
- 网页仅提示站点需要维护升级，不提供匿名或普通管理请求执行任意迁移的入口。

### 3.4 schema 2 的实际数据变化

- 添加 `site.description`、`site.language`、`site.socialImage` 三个业务字段，仍保存在现有 JSONB 中，不为了添加文本字段另建通用配置系统。
- 迁移为已有草稿的缺失字段补默认值，同时补齐模板 schema_config 中的对应字段；保留其他键和值。
- 默认值：description 为 `""`，language 为 `"en"`，socialImage 为 `""`。语言默认保留当前 HTML 的 en 语义，用户可在后台选择中文；不从硬编码原站元信息自动补充品牌、域名或分享图。
- 迁移使已有草稿 revision 增加一次，使升级前打开的编辑器不能无冲突覆盖升级后的配置；重复运行不再次增加。
- 现有 versions/previews 的 snapshot 不批量改写；读取时使用纯兼容投影，旧版本恢复为草稿时补齐默认字段再执行现有验证和 revision 检查。
- 新内容包/旧 SQLite 的导入、首次安装与后续版本恢复复用同一兼容投影规则，避免各处生成不同字段集合。
- 数据库 schema 2 与既有 snapshot format 2 是两种独立版本，不能混用；本阶段不因为数据库升级而假造新的历史快照格式。

## 4. 站点身份数据与验证

| 字段 | 规则 | 用途 |
| --- | --- | --- |
| title | 沿用现有标题规则 | 网站名与页面标题后缀 |
| description | 普通文本，最长 500 字符，可空，不接受 HTML | 默认描述与分享描述 |
| language | 受控选择 `zh-CN`、`zh-TW`、`en`，默认 `en` | HTML lang；本阶段不是多语言内容系统 |
| socialImage | 可空；现有资源选择器中的图片，或合规 HTTPS 图片外链 | 默认 OG/Twitter 分享图 |

- canonical 的 origin 只使用部署端 `SITE_ORIGIN`，不在后台新增第二个可冲突的域名配置。
- 不信任请求 Host、Forwarded、任意 query 提供的 canonical 或 origin。
- 外链只记录与验证地址，不服务端下载、探测内网或转换成代理请求。外链可达性沿用现有“未验证/警告”规则。
- 分享图必须作为图像资源引用进入登记、草稿/版本引用、发布检查和公开 URL 映射；禁用、回收或缺失的托管资源不能通过元信息绕过权限访问。
- 图片种类由服务端验证，不能只依赖前端选择器。导入包含历史版本的内容包时，也要收集每个历史版本自己的 socialImage，不只收集当前草稿的图片。
- 各字段按职责校验：描述不要求存在于旧 3D 字体图集中，语言枚举和图片 URL 不作为场景文字进行字形校验。
- 不能把整个 `site` 递归扫描为资源授权；只新增明确的 `site.socialImage` 资源槽位。

## 5. 页面元信息生成

建立独立的纯页面元信息解析/渲染模块，由当前已解析的发布快照、可信 origin 和规范化路由生成。服务器首个 HTML 响应必须正确，不能只等 JavaScript 启动后再修改。

| 路由 | 标题 | 描述 | 图片 |
| --- | --- | --- | --- |
| `/` | site.title | site.description | site.socialImage |
| `/work` | 非空 navWork + ` · ` + title；navWork 为空时只用 title | site.description | site.socialImage |
| `/work/:slug` | 非空作品 name + ` · ` + title；name 为空时只用 title | 作品 description 非空时优先，否则 site.description | 作品 image.url 非空时优先，否则 site.socialImage |

- 作品匹配只在该次请求的发布/预览快照内进行；不存在的 slug 返回真实 404、noindex 与通用错误页，不伪装成功作品。
- canonical 和 og:url/twitter:url 使用可信 origin + 对应规范路由，不包含 preview、跟踪 query 或 hash。
- 每种元信息只输出一个：title、description、canonical、og:title/description/url/type/image、twitter:card/title/description/url/image；空描述/图片对应标签省略。
- `og:type` 使用 website；有图时 twitter:card 为 summary_large_image，无图时为 summary。
- 分享图片需绝对 URL；已经登记的图片统一先通过该版本资源映射，再以可信 origin 解析。S3/外链也走现有受控版本资源入口再重定向，外部最终 HTTPS 地址保持原有查询编码，不能直接绕开资源授权。
- 更新 HTML lang 与 apple-mobile-web-app-title；移除受本模块管理的原站身份标签，其他字体、样式与启动脚本不顺带重写。
- 所有文本、属性正确转义；禁止描述、标题、URL 注入 HTML/脚本。HTML 属性转义与脚本数据序列化分开处理，不以删除合法的美元符号、反引号或反斜线代替安全编码。
- 管理页面与预览响应使用 `Cache-Control: private, no-store` 和 `X-Robots-Tag: noindex, nofollow`；预览 HTML 同时带 robots meta。覆盖预览 config/bridge/app/shader/资源等全部依赖端点，不只覆盖 `?preview=` 的 HTML；保持 owner/session/expiry 校验。
- 预览 canonical/share URL 使用无预览参数的公开路由，图片 URL 不变成匿名公开授权。
- 浏览器内从首页进入作品、作品间切换和返回列表时，元信息不能被旧引擎恢复为原站值。复用同一解析规则/数据投影，接入已识别的导航生命周期，不增加全局 DOM 轮询。
- `metadata.json` 仍是既有引擎模板接口，保留其按历史 snapshot.template.metadata 读取的语义，不将它直接替换为新的 SEO 对象。

## 6. 模块边界

- 迁移层：受控版本注册表、状态检查、事务执行；运行时轻量检查与完整结构预检职责分离。
- 站点契约：新字段默认值、校验及旧数据纯投影。内容、导入器、恢复流程和管理端共享定义，不复制分叉规则。
- 元信息层：路由/快照 → 元信息对象 → 安全 HTML，不查询数据库、不写文件、不操作存储。
- 前台路由：只把已经授权解析的快照与可信 origin 传给元信息模块。
- 资源链：只增加社会分享图的明确槽位，不另建不受现有引用保护的上传路径。
- 管理端：网站设置中增加描述、语言选择和分享图片选择/清空，沿用保存草稿、预览、发布流程；不引入第二套保存接口。

文件与函数的精确划分将在本规格批准后写入实施计划。本规格不把随意移动文件作为成果。

## 7. 错误、回滚与数据安全

- schema 1 + 新应用：显示需要升级；数据库故障/未知版本显示不可用，安装写入保持关闭。
- 升级失败：事务回滚，退出非零；不尝试删除 schema 或自动重新安装。
- schema 2 + 旧应用：明确不承诺直接二进制回滚，因为旧应用只接受 schema 1。恢复方案是维护窗口中的已验证备份恢复，不提供破坏性 down migration。
- 当前业务库的正式备份、迁移和切换是单独操作，须先报告精确目标并获得授权。本阶段测试不调用未指定隔离配置的 createApp/loadOptions/CLI。
- 真实数据库、uploads、S3 对象、主密钥和当前运行中的网站均不作为测试夹具。

## 8. 验收矩阵

### 数据与升级

1. 干净 PostgreSQL 18 新安装完成于 schema 2，账号/安装令牌/CSRF 防护与现有测试一致。
2. 用原始 001 创建的隔离 schema 1 fixture，含管理员、草稿、资源引用、已发布与历史版本，能显式升级至 2。
3. 升级前后账号哈希、资源/作品 ID、存储密文、已发布指针、历史 snapshot JSON 内容一致；只有规定的草稿/schema_config 默认值、revision 和迁移元数据变化。
4. 重复升级、并发升级只产生一次 002 记录和一次 revision 增量；故障注入能验证事务回滚。
5. 001 校验和不变；缺号、篡改 checksum、未知未来版本、结构漂移和数据库不可达均不能重新开放安装。
6. 空白、内容包、旧 SQLite 导入和旧版本恢复都得到相同字段契约；SQLite 只使用专门生成的临时 fixture，绝不使用真实 data/site.db。

### 内容与路由

7. 首页、作品列表、存在/不存在的作品路径输出正确状态和元信息；无 JS 读取首个 HTML 也能获得元信息。
8. 特殊字符与 HTML 注入输入被拒绝或安全转义；恶意 Host 和 query 不能改变 canonical origin。
9. 旧快照缺少新字段可以展示/恢复，不改写其历史行；空分享图/空描述不回退原站素材。
10. 社交图片本地/S3/外链映射均遵循现有引用与公开规则，未发布、禁用、回收和缺失资源不能越权曝光。
11. 认证预览保持 private/no-store/noindex，匿名不能通过预览图片引用访问草稿。
12. 浏览器导航后标题和元信息一致；后台新字段保存/预览/发布可用；原 Logo、黑洞和作品路径进行真实运行包回归。

### 测试与文档

13. 新契约与元信息纯测试不需要私有运行包或真实业务数据库。
14. 集成测试使用明确隔离 PostgreSQL 和临时媒体目录；缺少授权运行包时引擎验收标记未验证，不把跳过记为完整成功。
15. 更新 README、管理说明和 PostgreSQL 升级文档，清楚区分首次安装、显式升级、历史兼容和备份恢复。
16. 记录实际执行命令、通过/失败/跳过数量及未验证边界，不沿用上一轮 199 项结果作为新版本证明。

# 阶段 B：引擎契约与可追溯发布

日期：2026-10-14（Asia/Shanghai）。

状态：用户已确认采用“引擎适配层 + 固定运行包 + 校验后发布”方向及范围。本文件是据此细化的书面规格，尚待用户审阅；不是已经实现或验收的功能。阶段 A 已合并，设计基线为 `fb5117b`，分支 `feat/authenticated-resource-admin`。

总体设计：[个人主页架构改造](2026-10-13-architecture-modernization-design.md)。前置成果：[阶段 A 验证与合并记录](../../verification/site-identity-upgrade.md)。

## 1. 目标与方案选择

解决“内容版本已经固定，但旧版本仍读取当前目录程序”的问题。新发布必须明确绑定当次实际使用的运行包与构建规则，程序和生成文件在之后的请求中保持相同字节；生成失败不能改变当前公开版本。

已比较并选择：

1. **引擎适配层 + 固定运行包 + 校验后发布（采用）**：适合单站点、自托管、单应用实例，无额外构建服务。数据库记录身份与授权关系，私有本地目录保存字节。
2. **只拆补丁并增加检查**：工程量较小，但不能避免历史版本随当前文件变化，不能满足本阶段目标。
3. **独立构建服务、队列、云产物库**：适合更大规模，增加部署与故障处理复杂度，不纳入当前个人主页范围。

“可重复交付”指同一已绑定清单交付相同程序/生成文件，不等于完整网站所有媒体永不变化，也不承诺任意未来版本的构建器能重建旧字节。保留完成品是历史交付的基础；不能用最新构建器重建并覆盖旧身份。

## 2. 不变的边界

- 保留 Node.js >=24、PostgreSQL 18、CommonJS、现有原生管理界面及单站点/单管理员/单应用实例模式。
- PostgreSQL 仍是业务内容、交付绑定与访问授权的权威来源；私有目录不是可单独编辑、独立授权的第二份业务数据库。
- 保持 Logo、黑洞形状、粒子效果及场景参数语义。移动或规范化现有补丁不等于重新设计视觉；不覆盖用户的实验脚本和未提交素材。
- 保留草稿 revision、认证预览、发布历史、资源引用保护、审计、CSRF/Origin、HTTPS 与凭据加密。
- 本地/S3/外链业务媒体继续走现有资源服务。不自动下载远程资源、不把 S3 私钥放入清单、不把字体/图片/模型当程序旁路公开。
- 本阶段不做全量媒体归档、云产物存储、多实例构建协调平台、后台任务队列、公开运行包上传/插件执行、完整静态降级网页或管理端全量拆分。
- 不建立断库离线公开服务；数据库不可用时服务端失败关闭。后台、预览及错误响应不能进入公共缓存。
- 真实 `.env`、业务库、`data/site.db`、uploads、S3 对象和当前 3000 服务不作为实现测试对象。正式升级、服务切换、推送与部署均需独立授权。
- 详细实施继续使用独立工作区、明确的隔离 PostgreSQL 和临时资源目录；不把授权尚未明确的运行包文件提交到 Git。

## 3. 当前源码依据

- `admin-server/frontend.js` 的版本路由虽先解析内容快照，但仍在请求时读取当前 app、shader、shared identity 和 `index.html`；JS/CSS/WASM 另有静态目录入口。
- `admin-server/importers/disk.js` 的 `appFile()` 按文件名字典序选择最后一个 app，不是历史运行包标识。
- `replaceClass()` 在类缺失时原样返回，多数 `.replace()` 没有匹配次数校验；shader 段和替换锚点也未形成统一契约。
- `engine-assets.json` 是资源发现/加载器槽位清单，混合媒体与 program；`resource-catalog.js` 排除了 program。不能将它直接视为完整运行包清单。
- `config.publish()` 已有“锁站点 → 重查 revision/资源 → 写版本与引用 → 切 published → 写审计”的事务基础，应保留。
- `composeSnapshot()` 固定输出 `format: 2` 并重建字段白名单；直接给 snapshot 顶层添加运行身份会被导入、发布、预览再次投影时丢弃。
- 当前媒体路径使用最新资源状态授权，再读取本地字节或重定向外部地址。运行包固定不能改变这一撤回机制。

## 4. 三种独立版本与术语

| 概念 | 含义与边界 |
| --- | --- |
| 数据库 schema 3 | 本阶段新增表与交付关系的结构版本；显式迁移，不代表内容 JSON 改版 |
| 内容快照 format 2 | 继续承载 config/template/assets/legacyMap；既有历史 JSONB 不改写 |
| manifestVersion 1 | 新运行包/交付清单的数据契约，与数据库及内容版本分开命名 |
| 运行包 runtime bundle | 显式登记、经受控 profile 验证的程序输入集合；用内容摘要识别 |
| 交付 artifact | 运行包、快照、版本标识、可信 origin 和构建器共同生成的完整文件集合 |
| pinned 绑定 | 升级后正常发布/预览产生的固定交付，绑定建立后不可替换 |
| legacy 绑定 | 旧内容的明确标记；允许尚未生成兼容交付，不假造原始运行包 |
| legacy-render 产物 | 管理员后来显式为旧内容首次生成的兼容交付；一旦绑定也不替换，记录现在的生成时间和包身份，不代表历史原样重放 |

## 5. 模块职责

1. **受控旧引擎适配器**：唯一集中处理旧类名、shader 锚点、UIL 规则及遗留程序路径的模块。输入固定程序字节、快照公共投影和构建上下文，输出生成文件及补丁报告；不写数据库、不切 published。
2. **运行包登记与 profile 校验器**：从管理员明确提供的受信任本地目录及清单读取文件，验证路径、哈希、必需依赖和支持契约，登记不可变包身份；不扫描选择最新 app。
3. **私有产物存储**：接收确定的字节，按 SHA-256 寻址写入、验证和读取；不知道账号、草稿或哪个版本公开。任何对象存在都不等于获准公开。
4. **交付仓储与构建用例**：管理运行包选择、构建上下文、交付清单与版本/预览绑定；负责提交前复检和原子发布。
5. **前台交付路由**：先通过数据库、绑定和预览身份检查，再读取相应产物；不调用旧目录发现器，也不在请求中修补 app/shader。
6. **既有资源服务**：继续负责媒体引用、可用性、禁用/回收、本地范围请求和 S3/外链重定向。

本阶段只围绕这些边界调整现有热点，不把 C 阶段的所有路由、SQL、控件重组提前实施。

## 6. 运行包登记与严格契约

### 6.1 来源、选择与安装体验

- 运行包只能通过服务器端显式管理命令登记。输入是受信任本地根目录、清单路径和受支持 profile，不接受管理 HTTP 请求提交任意本地路径，不下载 URL，不执行导入目录中的安装脚本。
- 清单明确主 app 文件和每一项程序输入；目录中出现新文件不会自动登记或切换。登记和选择是两个动作：登记成功不自动替换当前选择或公开版本。
- 后台增加小型“运行包”状态区：展示已登记包的标识、profile、摘要、文件数、大小与当前选择；管理员可显式选择已验证的包。选择操作沿用认证、CSRF、Origin、冲突提示和审计。
- 选择保存在数据库，带独立递增 generation。重复选择同一包为无变化；选择其他包增加 generation。选择只影响以后构建，已绑定版本不受影响。
- 新安装仍允许没有完整运行资源；账号和数据库可以先初始化。没有选定有效包时，新发布/预览明确提示先登记并选择授权运行包，不偷偷选择目录中的文件。
- 旧库迁移仅创建数据结构与 legacy 标记，不读取磁盘、复制程序、选择运行包或触发构建。运行包登记、选择和交付生成是之后的显式动作。

### 6.2 profile 与原始清单

profile 随应用源码维护，定义唯一名称/版本、支持的模板结构、程序角色、依赖映射、大小上限以及补丁规则。任意上传清单不能自称受支持 profile，也不能放宽必要检查。

原始清单使用 `manifestVersion: 1`，包含 profile/template 契约身份、主入口、每项逻辑键、受限相对路径、角色、字节数与 SHA-256。摘要来自已读取的真实字节和确定性序列化清单；不采信提交方填写的哈希而不复算。内容摘要不包含机器绝对路径、文件 mtime 或登记时间，后者只作审计元数据。

当前六场景 profile 的程序闭包覆盖：入口 HTML、必要的不支持页面、主 app、modules/启动器、辅助 JS、worker 入口及其程序依赖、WASM、`compiled.vs` 等 shader 源码、实际存在且引用的 CSS。identity/bridge 等应用生成代码由构建器来源摘要单独覆盖。`assets/shaders/reel.mp4` 等媒体即使与程序同目录，也不能进入程序清单。

静态引用与已知动态引用都必须可枚举：例如 hydra worker、Draco wrapper/decoder、Basis transcoder、按配置使用的辅助库。未知动态程序路径判为不兼容；不是“在页面看起来没报错”就算闭包完整。没有使用的文件、source map、备份文件和目录中其他文件不自动公开。

登记限额：单个程序输入不超过 32 MiB，包总字节不超过 128 MiB，最多 512 个清单项。文件必须是普通文件、位于规范化根目录内；拒绝符号链接、绝对路径、`..`、编码穿越、重复逻辑键及同一路径的冲突角色。超限或错误明确失败，不截断或省略必需文件。

### 6.3 补丁与程序寻址

- 每个补丁具有稳定 ID、目标文件/类或 shader 段、明确适用条件、预期匹配次数和后置条件。必需类/段必须存在且唯一；缺失不能被解释为不适用。
- 不适用只由已验证的配置条件决定，例如没有配置某个可选外链；必需文件、类或依赖缺失必须拒绝。
- 保留当前特殊字符安全、空文本/空作品生命周期、Worker 路径、Logo/黑洞参数和站点身份更新行为。保留引擎 `metadata.json` 原语义，不替换成 SEO 对象。
- 程序 URL 与媒体 URL 使用独立解析器。程序仅映射到绑定交付允许的逻辑键；媒体仍映射到版本资源 ID，不做通用 `/assets/` 放行。
- 主窗口和 worker 是独立环境。必须明确 worker 入口、相对程序基址、`importScripts`、worker 内 fetch/WASM 的有限映射；不能以主窗口 fetch 包装代替 worker 验证。
- 低层单补丁函数可以用最小字符串做单元测试；生产登记/构建入口始终执行完整 profile 检查。禁止生产 `skipMissing`、`fixture`、`strict:false` 或通过环境变量关闭验证。合成集成夹具只在测试代码中注入测试 profile，不进入生产注册表。

## 7. schema 3 与清单持久化

新增 `003` 迁移，保留以下原字节：

- `001-initial.sql` SHA-256：`bba88a72df8e7166646fdc56e6485c36078bf7e7fe4077125fdd7ebc682d2a15`。
- `002-site-identity.sql` SHA-256：`98fca286a9790bff1b10a74719c820f15e3d66b5054c459f87057b34151c7533`。

沿用 A 的连续迁移前缀、校验和、每版本结构签名、升级锁和事务。001/002 的预期结构签名不被 schema 3 指纹覆盖。schema 1 可按已有链显式升级至 3，schema 2 只执行 003；旧安装在升级前进入维护而非重新安装。任何服务器启动、登录或普通 HTTP 请求都不能自动迁移。

新增职责明确的关系：

| 关系 | 核心约束 |
| --- | --- |
| `runtime_bundles` | 运行包摘要主键、不可变清单、profile 身份、登记时间；同摘要不同清单拒绝 |
| `runtime_selection` | 单站点唯一记录，选中包外键可空，generation 非负；初始未选择 |
| `delivery_artifacts` | 交付摘要主键、不可变清单、运行包外键、生成时间与种类；清单版本受控 |
| `delivery_bindings` | 恰好一个 version_id 或 preview_id；各目标唯一并有外键；mode 为 pinned/legacy，包含绑定 generation |

pinned 绑定必须关联完整 artifact。legacy 绑定初始可无 artifact，之后仅通过显式兼容构建首次关联 `legacy-render` artifact。两者一旦有 artifact 都不得原地替换；需换包或改变生成输入时恢复为草稿并正常发布新版本。artifact 的目标种类、目标 ID、runtime、origin、源快照摘要必须与绑定相符，不允许跨版本或将预览产物借给公开版本。

绑定的唯一性、外键、目标 XOR、mode 与空值条件由数据库约束保护；manifest 中的嵌套一致性由受控仓储入口验证并在读取时检查。不存在绑定、未知 manifest 版本或不匹配不是 legacy，而是交付不可用。

003 为全部既有 versions 和 previews 建立明确 legacy 标记，不修改其 snapshot、ID、创建时间、owner、expiry 或 published。不修改管理员、云凭据、资源 ID 和现有引用。它不改变草稿内容/revision；运行包选择有独立 generation。新库也通过完整迁移链建立相同结构。

旧 SQLite/现有内容包导入的历史记录仍显式 legacy，即使其 INSERT 发生在 schema 3。正常发布/新预览必须 pinned；这条规则不误伤历史导入。现有导入器不是产物迁移协议：外来记录不能仅凭一个摘要声称拥有本地 pinned 产物。

恢复历史版本仍只恢复兼容投影后的草稿，执行 revision 检查；不复制其旧交付身份，不切 published。随后按当前选择及可信 origin 生成新的预览或发布版本。

## 8. 构建输入与私有字节存储

### 8.1 不可变构建上下文

每个候选固定：目标种类及最终 ID、源快照摘要、构建投影摘要、草稿 revision（适用时）、运行包摘要、选择 generation、profile/adapter/补丁规则身份、构建器及 shared 代码来源摘要、启动时验证后的 `SITE_ORIGIN`。legacy 首次兼容构建还记录预期未生成绑定的 generation。

源快照摘要针对数据库原始历史 JSON（新发布则为即将存入版本的同一合法 JSON），不补字段、不执行当前适配器。构建投影是指定投影/adapter 版本对源快照的纯转换，另有身份与摘要。读取已固化交付时核对源快照，不能用新版适配器重新投影旧内容，再把差异误报为旧产物损坏。

摘要采用明确的确定性 JSON 序列化：对象键递归排序，数组顺序保留，禁止非 JSON 值；文件哈希针对原始字节。不把数据库 JSONB 的文本顺序、时间戳或临时路径作为内容身份。生成结果不得引入当前时间或随机串，目标 ID 等差异已经属于输入。

交付清单至少包含上述输入身份、全部生成文件的逻辑键/角色/MIME/大小/摘要、页面路由表、有效媒体引用/槽位及依赖集合的摘要、逐项补丁报告。清单本身保存在数据库；目录内即使有同名 JSON，也不能替代数据库授权。

有效媒体引用在构建时按绑定 profile/模板规则求得，最终事务把同一集合写入现有 `resource_references` 并校验一致。历史交付依赖该固定授权集合，再检查资源当前状态；不能继续使用当前 `engine-assets.json` 或新版适配器重新计算历史活动槽位、扩大/缩减原有授权。legacy 兼容交付只可使用该旧版本既有引用集合，不借新 profile 增加授权；确需新增引用时恢复并新发布。

### 8.2 私有 CAS

原始程序和生成文件放在 `SITE_DATA_DIR` 下专用 `delivery/` 子目录，按内容摘要去重。暂存目录由系统创建唯一名称；对象路径只由受验证摘要派生，不使用请求路径、用户名或上传文件名拼接。

先在私有暂存区完成写入、哈希和完整性检查，再以不覆盖既有对象的方式固化；已有同摘要对象必须核对字节。读取先检查路径边界、普通文件和内容哈希，再交付相同已验证字节。不能仅凭 mtime 判定内容正确；对象损坏不原地“修复”为新字节。

单次生成交付总字节不超过 256 MiB、最多 4096 项；越界失败，不生成部分可发布结果。运行包登记或构建过程不执行导入 JS/WASM；浏览器中的行为验收另在隔离环境进行。

目录不能被 express.static、反向代理或 CDN 直接公开。程序响应只能经数据库绑定路由获取，不能提供“知道哈希即可下载”的通用公开入口。新目录与 uploads 一样属于私有持久数据，容器重建不得丢失。

### 8.3 失败、占用和清理

文件系统与 PostgreSQL 不宣称共同事务。先固化私有完成品、最后提交数据库；失败至多留下不可公开的无主对象。自己拥有的暂存目录在异常/完成后清理；不得因为一次构建失败就删除可能被其他交付复用的 CAS 对象。

本阶段不做自动、在线或按“非当前版本”清理。历史版本引用的原始包和交付必须保留，注册包及有效预览也不能删除。提供存储占用/未引用对象的只读诊断，并记录备份与显式停机维护要求；自动垃圾回收是后续独立工作，不以保留临时垃圾为理由冒险删除历史。预览到期删除权限绑定后，字节即使暂留也不能访问。

## 9. 发布、预览与 legacy 兼容流程

### 9.1 正常发布

1. 在短暂一致性读取中捕获草稿、revision、选择的运行包及 generation；执行现有配置/资源检查。要求选中包存在且通过完整 profile 验证。
2. 从版本 identity sequence 预留最终正整数 ID，接受失败留下编号空洞。**普通预留发布不得复用会执行 `setval(MAX(id))` 的历史导入路径**；后者仅用于受控首次历史导入，不能回拨并发候选已经预留的编号。
3. 释放站点写锁，在私有目录构建主程序、辅助程序映射、shader、identity/bridge、config/UIL/projects/contact/metadata、不支持页面，以及首页、列表、每个已验证作品路径的 HTML。`snapshot.assets[*].document` 中的 Web App Manifest 等快照派生资源文档也在此生成并固化，保留资源 ID 到该派生文件的映射。页面元信息继续复用 A 的规则，构建时已经转义并生成正确 canonical。
4. 验证闭包、必要补丁、HTML/head 单一性、文件哈希及路径授权映射，固化全部产物。失败不写 versions 或切 published。
5. 最终短事务沿用“站点行锁 → 有序资源锁”的顺序，重新检查草稿 revision、运行包选择 generation/摘要、资源及存储可用性。提交上下文必须仍属于同一可信启动配置；origin 不是数据库列，不能虚构 origin 行锁或从请求 Host 更新它。
6. 在同一事务插入预留 ID 的内容版本、资源引用、artifact 记录、pinned 绑定、published 指针及审计。任一步失败整体回滚；新候选字节不产生公开资格。

长时间构建之后，HTTP 发布/预览还需确认发起管理员仍有效且其会话未因退出、过期或账号重置被撤销。并发不同候选不允许发布混合 revision；资源被禁用或回收、运行包被切换时旧候选拒绝提交。

### 9.2 新认证预览

采用相同构建与校验流程，提前生成最终 preview ID，输出 URL 保持 preview 命名空间。最终事务重新核对草稿/选择/权限，写预览、引用、pinned 绑定及审计；expiry 从成功提交时间起算，维持现有 30 分钟和每人最多五个预览的规则。

预览被替换、过期、退出登录或更换管理员后，各依赖端点仍检查 owner/session/expiry。删除过期 preview 时级联移除交付绑定；不把仍存在的 artifact 行或磁盘字节当作权限。预览成功不改变 published，发布不直接复用目标 ID/origin 不同的预览产物。

### 9.3 旧内容的明确兼容交付

- 迁移完成后，旧版本/旧预览有 legacy 标记但没有虚构的原始程序身份。无兼容产物时，前台显示交付需要维护的 503，不偷偷读取当前 app 文件。
- 后台版本列表提供受认证、CSRF/Origin 保护的“生成兼容交付”动作，参数为目标旧版本 ID 与预期 binding generation。它只使用全站 `runtime_selection`，不接受请求级 runtime/path/origin 覆盖；需选择其他包时先完成运行包选择。管理员也可恢复旧内容为草稿后正常发布新版本。前一种动作不修改历史快照或 published 指针，若目标恰是当前公开版本，仅补充其兼容交付。
- 兼容构建使用旧快照的纯兼容投影、当前显式选择和当前可信 origin；不能用当前草稿替换旧内容。模板不兼容或资源不可用时失败，不改变现有绑定或公开指针。
- 提交时复检 legacy 绑定仍未关联 artifact、generation、运行包选择和资源状态，原子首次关联 artifact 并记审计。pinned 版本或已有 legacy-render 的版本禁止通过此动作换包；之后改变包、origin 或内容必须恢复并发布新的版本 ID。这也避免浏览器先取得旧 HTML、后取得同一 URL 下另一代 worker/shader 的跨请求混包。legacy-render 不改变“原始运行包未知”的事实。
- 旧 preview 不补建兼容交付，提示创建新的认证预览；旧 preview 行/到期时间保持原样，直到现有过期清理生效。
- 升级手册必须明确维护顺序：备份 → 显式迁移 → 登记/选择运行包 → 为当前 legacy 发布生成兼容交付，或显式发布新版本 → 验证后恢复服务。不得把数据库迁移完成写成 3D 网站已经可用。

## 10. 请求交付、域名与缓存

### 10.1 只读交付入口

所有公开页面与 `/api/site/:version/*` 的程序/派生数据共用绑定解析：数据库安装状态正常 → 目标存在 → preview 授权（适用时）→ 明确 binding → manifest 受支持且目标匹配 → origin 相符 → 对象完整 → 响应。

已完成的历史交付只依赖受支持的交付清单格式、固定授权关系和完整字节，不要求当前应用仍装有原构建器/profile，也不重新执行旧构建规则。受支持 profile 是登记和新构建的条件；交付清单格式不受支持则明确失败，不能通过现场重建“修复”。

保留原有 `config`、`identity.js`、`bridge.js`、`app.js`、`uil.json`、`projects.json`、`compiled.vs`、`metadata.json`、`contact.json` 逻辑端点，但固定版本改为读取其清单中的完成品。首页/作品路由按清单路由表读取已生成 HTML；不存在作品仍是真实 404、noindex、不启动引擎。不在请求时重建缺失文件或重跑补丁。

辅助程序使用版本化 runtime 端点，由受限逻辑键查清单。主窗口/worker/CSS 的相关引用均指向该命名空间；不保留可读取当前目录的 `/assets/js`、`/assets/css` 静态兜底。不支持页面同样绑定版本：引擎跳转改用该版本的交付入口；顶层 `/unsupported.html` 仅作为解析当前公开交付（或经认证 preview）的兼容入口，不能继续静态读取当前文件。

业务媒体的旧路径兼容仍需先映射资源 ID、走固定版本引用集合与实时状态检查，不能借程序静态路由绕开。快照派生资源文档通过原资源 ID 端点读取绑定的固化文件，也必须检查资源禁用/回收、预览和 origin；不能以 program 角色跳过授权，不再请求时执行当前 `mapResourceTree()` 重写。普通媒体原始字节仍由既有存储提供，不纳入 CAS 固化承诺。

内部对象键、绝对路径、完整清单中的服务器信息不直接泄露在错误消息中。公开文件 MIME 由清单角色决定，保留 nosniff，不让装饰文件名改变实际字节或类型。

### 10.2 域名变化

规范化 `SITE_ORIGIN` 是构建输入，来源只限服务器启动配置。公共页面、程序及派生数据在交付解析时比较当前 origin 和绑定 origin；不一致返回维护 503/no-store，不改写旧 canonical/bridge，不降级成 legacy。

更换域名后，后台仍可读取历史配置和安全交付摘要。管理员在新 origin 下生成新预览，并显式重新发布；已经绑定的 pinned 或 legacy-render 均保留原值、不原地换域名。尚无 artifact 的 legacy 可按首次兼容流程生成。普通媒体原始字节的独立授权入口继续保持原规则，不因域名变化变成新的公开资源授权；派生资源文档则执行上述交付 origin 检查。

### 10.3 第一版缓存策略

| 响应 | 策略 |
| --- | --- |
| 管理、安装、全部预览及依赖 | `private, no-store`，`noindex, nofollow`，包括失败响应 |
| 公开 HTML、配置 JSON、CMS 派生数据、业务媒体/重定向 | `no-store`；本阶段不改变媒体撤回语义 |
| pinned 的公开程序、CSS、WASM、shader | 按已验证字节摘要生成 ETag，`public, no-cache, must-revalidate` |
| legacy-render、交付异常、404/503 | `no-store`；错误页保持相应 noindex |

第一版明确**不开启长期 `immutable` 缓存**。允许缓存的程序也必须回源验证；304 只能在数据库、绑定、origin、预览/公开范围及对象完整性检查通过后返回。数据库故障不能因命中 ETag 直接成功。以后若需要 CDN 长缓存，另行定义失效/撤回和离线语义，不混入 B 的首次实现。

## 11. 运维、后台提示与恢复

- 管理端提供安全的运行包与交付状态：未选择、不支持、构建冲突、缺文件、损坏、origin 不匹配、legacy 待兼容、pinned 就绪。列表摘要不能泄露本地路径/密钥。
- 发布/预览仍为请求内完成，不引入后台队列。按钮在请求期间防重复提交，成功后才更新版本信息；客户端取消不等于服务端事务回滚，响应丢失后通过版本列表/审计核实，不自动重复发布。
- 操作错误不包含完整连接串、服务器私有路径或源代码；服务端诊断可记录候选 ID、目标 ID、摘要和失败阶段，不打印秘密。
- 备份必须在维护窗口阻止新构建与写入，等待在途构建结束后，一致保存 PostgreSQL、`delivery/`、uploads、授权 bundled 媒体与主密钥；原始授权包可另外保留作重新登记来源。S3 对象备份仍由存储方负责。
- 恢复先在隔离环境验证数据库关系、对象摘要、运行包/交付可读取、历史及预览权限，不能只恢复数据库后声称完整恢复。缺失对象从匹配备份恢复，不重新指向当前文件。
- schema 3 与旧应用的直接二进制回滚不作兼容承诺。回退使用维护窗口中的已验证整套备份，不提供破坏性 down migration。
- 测试、README、管理指南、迁移指南及容器持久化说明随实现更新。本规格本身不声称这些工作已经完成。

## 12. 验收矩阵

### 运行包与适配

1. 相同清单/字节在不同目录和 mtime 下得到相同包摘要；任一程序字节变动得到新身份，不覆盖旧包。
2. 目录含多个 app 时只使用显式清单入口；增添更大的文件名不影响已有包或历史交付。
3. 缺文件/类/shader 段、重复锚点、错误哈希、未知依赖、路径/符号链接逃逸、配额超限均失败关闭。
4. 主窗口、worker、WASM、CSS 和不支持页面保持版本绑定；未声明程序不能从原静态目录读到；字体/图片/模型继续走资源授权。升级当前 adapter/inactiveLayouts 不改变历史有效引用集合，新增引用必须新发布。
5. 保留空文本/空作品、特殊字符、身份导航、Logo/黑洞参数与 metadata.json 契约。真实授权包缺失时标明完整引擎未验证，不能用合成 fixture 替代该结论。

### 数据、构建与并发

6. schema 1/2 → 3、新安装、重复/并发升级、故障回滚均验证；001/002 原摘要不变，历史 JSONB、账号、凭据、发布指针不被迁移改写。
7. 迁移/导入创建明确 legacy 标记；新正常发布/预览创建 pinned；缺绑定或新产物损坏不退回 legacy。
8. 构建、写盘、清单插入、引用更新、审计失败都不改变旧 published；孤立对象不能匿名请求。
9. 构建期间改草稿、切运行包、禁用资源/存储、注销会话或重置账号，提交复检拒绝陈旧候选。
10. 两个候选预留 ID 后逆序完成、一个失败等情形不回拨 sequence、不复用 ID；历史导入同步 sequence 与正常候选分开测试。
11. 源程序在登记后被覆盖/移除不改变 pinned 交付；CAS 对象缺失/篡改明确拒绝，不回源。构建输入相同时输出确定，生成时间不污染内容摘要。
12. legacy 首次兼容生成不改变历史配置/创建时间，不允许替换 pinned 或已有 legacy-render；并发首次兼容构建只能一个成功绑定，不会在依赖加载期间换包。恢复历史只改草稿，新发布使用当前显式选择。

### 交付、安全与浏览器

13. 未发布候选、过期/其他 owner 的预览、退出后的预览、私有 CAS 直接路径均不可访问；预览所有依赖和错误均 private/no-store/noindex。固化的 Web App Manifest 等资源文档也保持资源授权、origin 与预览检查，不能借程序入口访问。
14. ETag 只能在重新授权及校验后返回 304；断库、损坏、错误 origin 不因缓存成功；媒体禁用/回收仍即时影响后续服务端请求。
15. 改 `SITE_ORIGIN` 后旧 pinned 公共交付失败关闭，后台历史可读取，新 origin 显式生成的新版本元信息正确；Host/query 不能改变 trusted origin。
16. 在隔离真实浏览器完成登记/选择、预览/发布、两版本程序绑定、legacy 兼容、首页/作品/Contact 导航、退出失效和视觉对照；不改黑洞/Logo，不以 HTTP200 代替画面检查。
17. 验证 Docker 包含适配器/profile/shared 模块、私有交付目录持久化且不公开；新安装缺授权包可设置账号，但发布提示准确。
18. 实际记录自动测试数量/失败/跳过、使用的包身份、运行环境、浏览器证据、隔离目标与清理结果。不沿用 A 的 242 项结果证明 B 已通过；真实 S3/CDN/生产部署仍单列未验证。

## 13. 交付拆分与设计自审

实施计划按依赖分成三个可审查批次，不分别放宽本规格：

- B1：提取受控适配器、profile/清单与路径契约，建立失败用例及现有效果兼容测试。
- B2：schema 3、私有 CAS、显式运行包选择、候选构建/原子绑定及 legacy 兼容流程。
- B3：接入全部交付入口、严格缓存/域名/预览边界，完成容器、浏览器、备份文档和整段独立审查。

自审清单：

- [x] 区分 schema/content/manifest 版本及 pinned/legacy/损坏，未假造旧运行身份。
- [x] 明确构建锁外、提交锁内、版本 ID 预留与历史导入 sequence 分离。
- [x] 明确 origin 来自启动配置、跨域名需显式新交付，不虚构数据库 origin 锁。
- [x] 明确程序与媒体分离、Worker 依赖、受限清单及生产检查不能跳过。
- [x] 明确文件与数据库非共同事务、孤立对象无公开权限、不自动删除历史。

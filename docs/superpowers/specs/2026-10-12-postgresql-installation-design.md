# PostgreSQL 数据统一管理与网页安装向导

日期：2026-10-12

状态：用户已确认详细规格（2026-10-12）；进入实施计划阶段，尚未实施。

实现基线：`bd7ef11`，分支 `feat/authenticated-resource-admin`。

## 1. 已确认的目标与边界

正式版本使用 PostgreSQL 保存全部业务数据、资源记录与引用关系；媒体文件本体仍放本地磁盘或通用 S3。首次部署在网页安装向导中初始化应用数据结构并设置管理员，不再要求通过终端创建首个账号。

本规格替代原后台设计中的 SQLite 主存储和终端首次创建管理员两项决定；保留单站点、单管理员、本地/S3、外链、草稿发布、GLB 转换及现有安全边界。

本次不引入 MySQL 或多数据库运行时适配，不提供多租户、公开注册、自动私有签名链接续期、字体图集自动生成、可视化任意着色器编辑或全站媒体自动迁移。SQLite 仅保留为旧版数据迁移的只读来源。

“全部从数据库加载”指：页面业务内容与资源选择以数据库为唯一权威来源，经后端公开接口提供给浏览器。不是把视频/模型作为数据库 BLOB，也不是让浏览器直接连接数据库。

## 2. 当前实现与需要解决的问题

- `admin-server/database.js` 使用同步 SQLite 和通用 settings JSON，资源、存储等列表整体读写；需要改成异步 PostgreSQL 仓储和独立记录。
- `config.js` 首次导入当前 UIL/CMS，但 `buildUIL()` 每次仍读取基础 UIL 文件。
- `frontend.js` 仍从磁盘读取 contact/metadata JSON；发布版本没有包含完整基础内容。
- 引擎中仍有硬编码媒体路径；只登记新上传文件不足以覆盖现有资源。
- `server.js` 启动即建 SQLite 表，账号由 `scripts/admin-account.js` 创建；没有可在数据库未就绪时运行的安装状态服务。
- 现有认证、上传、安全静态目录、模型转换及前台兼容补丁已经过本地测试，迁移时不能删掉这些保护，也不能重置现有 Logo、黑洞和作品。

## 3. 数据组织

PostgreSQL 使用独立应用 schema；部署连接仅对指定数据库/schema 授权，不需要数据库超级用户。

| 表或数据集合 | 责任 |
| --- | --- |
| schema_migrations | 已执行迁移及校验信息，防止重复或悄悄改变旧迁移 |
| installation | 单例安装状态、安装完成时间、内容来源、数据格式版本 |
| admins / sessions / login_attempts | 密码哈希、散列会话 ID、CSRF、有效期及登录限流 |
| site_settings | 当前草稿的网站信息、草稿修订号和已发布版本指针 |
| scenes | 场景顺序、类型、可编辑参数 JSONB、资源槽位；完整基础配置按站点模板版本保存 |
| projects / songs | 独立作品和音乐记录，带排序及资源引用 |
| storages | 本地/S3 配置与加密凭证；主密钥留在部署环境 |
| resources | 稳定 ID、来源、对象键/外链、类型、大小、校验值、转换状态、源资源 ID |
| resource_references | 草稿/发布版本中资源的引用者及槽位，支持查询和回收保护 |
| versions / previews | 不可变完整发布快照；带过期时间的认证预览快照 |
| audit_events | 登录、配置变更、发布、迁移和资源操作记录，不含密钥或密码 |

资源和作品不是塞进一个无限增长 JSON 数组。JSONB 用于场景参数、模板数据、快照等适合整体处理的文档；账号、资源、存储、引用等使用明确的字段、唯一约束和关联约束。业务校验按字段名匹配，不依赖 JSON 对象键的顺序。

版本快照包含完整网站配置、作品、音乐、场景基础配置、contact/metadata 和资源 ID 映射。发布事务更新版本指针，前台一次访问固定版本 ID，不能混读新旧版本。对原始程序包和远程第三方文件不承诺字节级历史恢复。

## 4. 资源登记与前台接入

### 4.1 哪些文件纳入资源库

- 网站使用的图片、视频、音频、模型、纹理及字体图集/字体资源。
- 本地原有文件登记为只读的 bundled 资源，记录白名单内相对路径和文件校验信息；不强制复制到 uploads。
- 新上传文件继续保存在私有 uploads 或 S3；外链只记录引用，不自动抓取。
- 图片图集和字体 JSON/贴图等成组依赖需要记录关联，不能只替换其中一个文件而遗漏另一部分。
- JavaScript、CSS、解码器 WASM、受版本控制的着色器代码等程序运行包随代码部署，不作为可由后台任意上传执行的业务资源。

### 4.2 初始化与运行时分离

导入阶段一次性读取当前 UIL/CMS、已识别的引擎资源清单及硬编码媒体引用，建立数据库模板和资源映射。所有静态配置读取集中到 importer，普通前台请求不再从旧 UIL/CMS 补齐业务数据。

对于引擎硬编码的媒体路径，建立受版本控制的兼容映射，转换为已发布版本的资源解析入口；覆盖 fetch/XHR、图片/视频载入和 Web Worker 模型路径。不能仅拦截主线程 fetch 后就声称全部资源已经接入。

数据库用于确定资源及权限，文件字节通过受控本地流或公开 S3/CDN 读取。解析结果可按不可变版本缓存，不要求每个分片读取都重新查完整配置。公开响应不得包含部署绝对路径、数据库连接串、存储密钥或未发布资源记录。

完整性检查产出两类结果：必需的程序/场景依赖缺失阻止标记该模板可用；已有可选媒体缺失或外链不可验证则记录明确警告，不静默回源下载，不擅自丢弃旧引用。当前已有的禁用资源和占位外链须在导入报告中明确区分。

### 4.3 空白内容

新部署可选择空白业务内容或导入随部署提供的内容包。空白模式不包含原作者的账号、联系方式、作品或云凭证；保留站点模板的结构约束。没有授权的 3D 程序/素材包时，后台仍可安装使用，公开页显示“尚未配置运行资源”，而不是加载残缺场景。

## 5. 网页安装流程

管理入口仍为 `/admin/`。后台壳和最小安装状态接口不依赖业务数据库已经完成初始化。

1. **安装授权**：填写一次性安装令牌。令牌由部署环境 `SETUP_TOKEN` 提供；缺少有效令牌时关闭首次安装写入功能并给部署者提示，不使用公共默认令牌。
2. **数据库检测**：后端读取部署环境 `DATABASE_URL`，向有安装权限的用户展示脱敏连接目标，检测网络、TLS、权限和已有安装状态。
3. **选择初始内容**：空白业务内容、当前部署资源包，或已准备的旧版 SQLite 迁移源。显示将导入的数量和缺失资源报告。
4. **创建管理员**：新安装填写用户名、密码、确认密码。校验沿用现有密码哈希和强度要求。旧站迁移时按第 7 节保留原账号，不无提示地覆盖账号。
5. **执行安装**：后端持有安装互斥锁，运行数据库迁移、导入基础配置和资源记录、创建管理员、写安装完成记录。显示状态与明确错误，不把密码或完整连接串写入日志。
6. **完成并登录**：安装完成后回到登录页，首次管理员使用刚设置的账号登录。之后在存储设置中配置 S3；S3 不是安装成功的必要条件。

本版数据库连接凭证通过部署环境配置，网页负责检测、初始化和错误指引，不开放匿名填写任意数据库地址并探测内网的接口。使用 Compose 内置数据库时由环境变量自动组成连接配置；外部数据库由部署者填入 DATABASE_URL。

“初始化数据库”指应用 schema、表、索引、初始数据，不是让网页安装 PostgreSQL 服务、创建云账号或获取数据库超级用户权限。

## 6. 安装安全与失败恢复

- 安装令牌在请求体或专用请求头传递，不出现在 URL、前端包、公开状态响应和访问日志中；只在安装授权阶段验证，比较采用恒定时间方式。
- 获取安装授权后使用短时 HttpOnly 安装会话；写入仍有 Origin、CSRF、限流、请求大小限制。生产强制 HTTPS 和 Secure Cookie。
- 使用数据库事务级互斥锁及 installation 单例约束；每次安装提交都在锁内重新检查完成状态。两个浏览器或两个服务进程竞争时最多一个成功。
- 当前版本首次建表/建索引的迁移应可在事务内执行；不在该事务中进行 S3 网络请求、大文件复制或模型转换。一次提交同时完成初始内容、账号和安装完成标记。
- 安装前扫描/校验失败不改变旧站数据；事务失败回滚本次数据库写入，并允许有令牌的部署者重试。不得执行 DROP DATABASE、清空非本项目 schema 或覆盖已有安装。
- 已安装后，设置新的 SETUP_TOKEN 也不能再次初始化；安装完成记录是权威依据。数据库不可达、查询报错或版本不兼容返回不可用/维护状态，绝不能被当作“新站未安装”。
- 后续软件升级执行显式数据库迁移，不复用首次管理员设置接口。管理员找回仍使用服务端受控恢复命令，不重新开放首次安装。
- 数据库切换到一个新的空库是新的部署，不自动找回旧站；文档需明确备份 PostgreSQL、本地媒体及独立主密钥，数据库成功备份不等于 S3 对象已经备份。

## 7. 从当前版本迁移

提供一次性只读导入器，不维持两个数据库同时写入。

1. 先停止旧实例的写入并备份完整私有数据目录，保留原 SQLite 及上传文件；迁移前生成数量/引用/缺失资源报告。
2. 迁移源由部署者在服务端指定和授权，不接受网页上传任意数据库文件或填写任意本机路径。
3. 迁移当前草稿、所有发布版本、作品、音乐、存储、资源、源/派生关系及必要审计记录；保留已有资源 ID 和旧媒体 URL 的兼容映射。
4. 若旧库已有管理员，保留其用户名和密码哈希，安装向导不允许静默替换；迁移完成后用原账号登录。若旧库没有管理员，在向导中创建。旧会话不导入，要求重新登录。
5. 云凭证维持原加密主密钥；缺少正确主密钥时不能把密文当作可用凭证，迁移报告明确要求恢复密钥或重新配置云存储，不回显秘密。
6. 验证行数、版本指针、资源引用和关键页面，再切换服务。切换前迁移失败可继续使用未改动的旧版本；切换后若产生新写入，不能直接回退旧 SQLite 而声称数据无损。

迁移不会自动把本地资源上传到云端，也不删除原文件，不把资产加入 Git。现有素材包授权问题与数据库迁移分开处理。

## 8. 模块与交付顺序

1. **持久层与迁移工具**：异步数据库访问、明确仓储、事务、schema 版本、旧数据预检/导入；保留现有接口契约以控制前台改动。
2. **安装服务与页面**：独立启动状态、令牌授权、数据库检测、安装事务及中文向导，首次安装不依赖管理员会话。
3. **配置与资源接入**：全量配置快照、资源登记/引用、原引擎兼容解析、发布和预览；取消普通请求对旧 UIL/CMS 的读取依赖。
4. **回归与部署**：Compose 增加 PostgreSQL 和独立持久卷、连接健康检查、示例环境、备份和迁移文档；隔离测试通过后才切换用户的本地实例。

各阶段在当前功能分支提交，不自动推送 GitHub 或公开部署。用户已有未提交的模型/效果修改不纳入本次提交。引入异步数据库后，逐个检查认证、上传、模型处理、配置发布中的 await 和事务边界，不能用同步内存缓存伪装数据库权威状态。

## 9. 验收标准

- 在真实隔离 PostgreSQL 上测试；不能用 SQLite 或内存对象模拟通过后宣称 PostgreSQL 已支持。
- 未初始化、数据库不可达、已经安装三个状态可区分；数据库故障不会开放安装接口。
- 无令牌、错令牌、CSRF/Origin 不符的安装写入被拒绝；令牌和数据库密码不出现在公开响应、前端或日志。
- 并发安装、重复提交、事务中断可验证，只产生一套初始数据和一个管理员；已安装实例不能被令牌再次覆盖。
- 管理员在浏览器安装并登录成功；原认证、密码变更、会话失效和限流仍有效。
- 旧库只读迁移后草稿、历史版本、资源引用和已转换 Logo 可用；不修改原 SQLite、素材文件或现有云对象。
- 初始化导入后，在隔离测试中移走原 UIL/CMS 配置文件，页面业务数据仍能从 PostgreSQL 解析和渲染；程序/媒体文件保留原存储。不得用进程内启动缓存掩盖缺少数据库快照，须重启后再验。
- 上传并发布后通过资源 ID 加载，覆盖图片、音乐、视频、模型及 Worker 路径；原 Logo 和黑洞视觉回归通过。
- 草稿不可被匿名访问；发布原子切换、版本恢复和被引用资源的回收保护仍有效。
- Compose 首次安装、重启后持久化和备份恢复分别记录实测状态。真实云厂商与 CDN/CORS 验收仍需有效凭证，不用本地测试替代。

## 1. 目标

把当前“旧 3D 运行包 + 内容管理后台”渐进整理为可维护、可升级、可供他人部署的单站点个人主页项目。保留现有视觉与功能，不用一次性重写取代已有实现。

成功标准不仅是页面能打开，还包括：全新安装与旧站升级分别可验证；历史内容可读取；新发布版本具有明确的模板兼容边界；后台模块能独立修改；没有 3D 能力时仍能阅读个人主页核心内容；他人能在干净检出目录重复执行测试与部署步骤。

## 2. 方案比较与选择

1. **渐进式模块化单体（采用）**：保留 Node.js、PostgreSQL、本地/S3 和原生管理界面，以接口和验收边界逐步替换耦合点。风险与维护成本较低，每阶段可以单独验证。
2. **仅修元信息与拆文件（不采用为完整方案）**：交付快，但不能解决数据库升级、引擎补丁失效和历史版本无法绑定运行包的问题；只作为第一阶段中的小步交付。
3. **更换整个前后端栈／重写 3D 引擎（不采用）**：会扩大视觉回归、资源授权与数据迁移范围，对当前单站点目标收益不足。

上一轮用户已要求“按照你的建议进行改造”，因此不再次询问数据库、微服务或框架选择；这里只确认更具体的交付契约。

## 3. 不变的边界

- 单站点、单管理员、单应用实例自托管；不引入公开注册、多租户或微服务。
- Node.js >=24、PostgreSQL 18；本轮不更换数据库、不强制引入 ORM。
- PostgreSQL 是业务内容和资源授权的唯一权威来源；文件字节仍在本地或 S3，外链不自动抓取。
- 发布产物是数据库内容的派生结果，不成为可独立修改的第二份业务数据源。
- 保留草稿、认证预览、发布历史、版本冲突检查、资源引用保护和审计。
- 保留当前 Logo、黑洞轮廓、粒子效果及场景参数，不重新设计视觉。
- 保留首次安装令牌、会话、CSRF/Origin、生产 HTTPS 和云凭证加密保护。
- 不自动读取真实 `.env`、连接或迁移当前业务库，不打开真实 `data/site.db`，不重启当前 3000 端口实例。
- 只使用明确的隔离数据库、临时媒体目录和测试端口进行执行验证。已有本地模型/效果脚本、`.gitignore` 等用户修改保持原样，不混入改造提交。
- 可以创建本地设计和实施提交；原设计不自动推送、合并或公开部署。后续完成交付目标已明确授权安全的本地集成与隔离 Docker 演示；该授权不扩大为 GitHub 推送、生产升级或公网切流。

## 4. 目标职责

```text
admin-ui：按功能组织的视图、共享控件、状态和 API 客户端
    ↓
应用模块：内容 / 资源 / 发布 / 账号 / 安装升级
    ├─ repository → PostgreSQL
    ├─ storage adapter → 本地 / S3
    └─ template adapter → 受控的旧引擎契约
    ↓ 发布
版本化交付
    ├─ 基础 HTML、页面元信息与资源清单
    └─ 绑定运行包的 3D 展示产物
```

路由处理输入输出和身份；业务模块处理流程、校验和事务；repository 管 SQL；模板适配层是唯一了解旧类名、UIL 键和源码补丁的位置。只拆已有跨职责热点，不为每个小函数制造多层包装。

## 5. 分阶段子项目

各子项目单独形成 spec → 实施计划 → 测试 → 审查 → 交付。下面是整体范围，不表示未完成阶段已经实现。

### A. 安全升级与站点身份（先实施）

- 支持有序、校验和固定的增量迁移，保持 `001-initial.sql` 原字节不变。
- 新安装创建当前版本；旧安装通过显式命令升级；未知结构、校验失败或数据库故障不得开放初始化。
- 增加描述、页面语言、分享图配置；首页、作品列表、作品详情输出一致的标题、canonical、OG 和 Twitter 元信息。
- canonical 只从可信部署 `SITE_ORIGIN` 和已验证路由派生，不接受 Host 头或后台任意 canonical 覆盖。
- 旧快照只在读取/恢复时做兼容投影，不修改历史数据库行。
- 为新增模块建立纯函数、隔离 PostgreSQL 与路由级回归测试。

详细规格：[第一阶段设计](2026-10-13-upgrade-and-site-identity-design.md)。

### B. 引擎契约与可追溯发布

- 把 `patchAppSource`、shader 和资源路径兼容集中到一个旧引擎适配模块。
- 对支持的运行包记录文件清单、版本/哈希和补丁匹配预期。必需补丁未命中时拒绝生成，不静默成功。
- 新发布记录确切模板/运行包身份，生成并校验派生产物后再切换公开入口；失败保留当前已发布版本。
- 新版本可重复交付；历史版本不能被伪造为拥有当时未记录的运行包。旧版本采用明确标记的 legacy 兼容策略，缺包/不兼容时不自动选择“最新文件”冒充原始版本。
- 缓存只用于已确认不可变的公开产物，保留资源禁用、回收和预览私有性。后台和预览不进入公共缓存。
- 第一版保留现有数据库不可用时失败关闭的策略，不偷偷增加“断库仍公开服务旧内容”；若后续需要离线交付，单独定义资源撤回和权限语义。
- 不抓取或归档任意第三方外链；即使绑定运行包，也不承诺远程第三方媒体字节永不变化。

详细规格：[阶段 B：引擎契约与可追溯发布](2026-10-14-engine-contract-and-traceable-publishing-design.md)，已由用户确认；[实施计划](../plans/2026-10-14-engine-contract-and-traceable-publishing.md)已按选择完成代码与审查，实际验收边界见验证记录。第一版采用私有本地产物存储，公开程序缓存必须回源检查，不启用长期 immutable 缓存；旧版本需显式生成兼容交付，不在请求时回退到当前目录程序。

### C. 前后台职责整理与共享契约

- 优先分离内容、资源、发布三个热点中的路由、用例和 SQL，维持现有 API 行为与事务保护。
- 拆分管理端 API、状态、通用控件及网站/作品/资源/存储/版本视图，保留中文文案、dirty 状态、确认弹窗与焦点恢复。
- 从业务内容定义共享校验/类型契约；先使用可渐进采用的显式数据定义与 JSDoc/checkJs，不把全仓 TypeScript 重写作为前置条件。
- 模板槽位与通用个人信息分离，保留已有六场景作为一个模板，不顺带开发任意拖拽页面搭建器。
- 建立 lint、格式化和类型检查入口，限定新改动范围，避免一次全仓格式化覆盖用户工作。

### D. 基础网页与可复现交付

- 从同一发布快照输出语义化简介、作品与联系方式，3D 作为增强展示；定义无 JS、WebGL 初始化失败和减少动态效果时的可用入口。
- 实测键盘、焦点、缩放、手机交互及关键视觉回归；性能结论必须有设备/网络条件与测量记录。
- 提供自有的最小示例内容和程序化素材，不把未经确认的原站素材加入 Git；代码许可选择与第三方授权清单由项目所有者确认，不擅自给现有素材重新授权。
- 把历史工具移到明确目录并保留可追溯性，不删除用户的实验文件。
- 建立持续集成：基础测试不依赖私有素材；完整引擎验收明确要求授权运行包，缺包不得显示为“完整 3D 已通过”。
- 增加无秘密信息的存活/就绪检查和请求关联日志，接入应用容器健康检查；保留备份、恢复和版本升级验证记录。

## 6. 验收与停止边界

- 每阶段先补回归测试，再改实现；只在完整隔离环境验证当前阶段涉及的数据行为。
- 最终检查不仅看新增测试，也要回归安装、认证、发布、存储和前台路径。
- 实施报告区分：源码检查、实际测试、浏览器验证、未验证的真实 S3/CDN/目标服务器行为。
- 若必须访问真实数据、重启当前实例、执行生产升级、分发有授权疑问的素材或推送 GitHub，先说明精确目标并取得对应授权。
- 不以“阶段 A 完成”声称整个改造完成；后续阶段继续按独立设计和验收推进。

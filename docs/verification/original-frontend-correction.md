# 原前端恢复与作品管理纠偏

## 用户要求

原有前端页面效果不变，只增加后台配置作品列表。原 Logo、粒子尺寸/反射、黑洞轮廓、场景、布局、动画及交互不是新设计范围。先前使用 `portfolio-v1` 示例作为验收站点不符合这一要求，不能再视为原站交付完成。

## 已查明的原因

- 原目录的 index、前台程序、shader、UIL 及视觉实验文件没有被改造成示例；错误发生在 Docker 验收实例选择并发布了另外的示例模板。
- 原内容包读取到 16 个作品和六个原场景。普通导入预检通过，但实际生成原页面时，新增的递归资源校验把 UIL 纹理描述对象的 `prefix` / `relative` 目录（例如 `assets/images`）当成待授权的文件，错误拒绝原站。
- 修正范围仅为按原 `render.mapUIL` 的规则校验真实资源源地址；geometry/initialPositions 的 relative 若是文件路径仍必须校验，其他非 UIL 资源校验不放宽。
- 安装界面恢复默认原内容包，不再推荐或默认选择不同的示例；示例选项明确警告它不保留原视觉。
- 删除原站发布包装中额外注入的“普通网页”悬浮入口、按 reduced-motion 强制跳转的脚本和 unsupported 页的不同布局覆盖层。`/contact` 直接访问也使用原前端程序；显式的 `/basic` 仅保留为独立地址，不再强行替换原站。

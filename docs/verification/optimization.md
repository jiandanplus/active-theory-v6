### 与原方案的偏差及原因

- **P3 没有做按时间过期的缓存。** 现有测试（`tests/delivery-http.test.js`、`tests/database-content.test.js`）要求：快照、manifest、引用、绑定、安装表一旦在数据库中被篡改或损坏，**下一个请求**就必须失败关闭。5 分钟 TTL 缓存会违反这一安全保证，所以改为：
  - 每个请求照常完整校验；
  - 合并重复读取：绑定、制品、运行包一条 JOIN；发布指针与快照一条 JOIN；
  - 安装状态在同一请求内复用；
  - 每个摘要只计算一次。

  剩余 6 条 SQL 为：安装检查 3 条、版本 1 条、交付链 1 条、引用 1 条。要降到 ≤ 2 条，只能缓存跨请求状态，这需要所有者先决定是否放宽「篡改即时失败」的保证。
- **P1 不缓存「已安装」状态**，原因同上：`database-content.test.js` 要求安装表被移除后立即返回 503。改为合并两条探测查询，并在请求内复用结果。
- **后台版本列表仍逐个完整校验每个版本**（含快照哈希），以保证被篡改的历史版本继续显示「缺失/损坏」。查询已从每版本 7 条降为固定 9 条；剩余耗时主要是 100 次快照哈希和 JSON 传输。
- **P5 改为新增 `document_assets` 表，而不是在 `resource_references` 上加列。** 原规则依据的是快照内容，而不是引用关系：一个未被引用、但在快照中标记为文档的资源，也必须拦截无目标访问。新增表从快照派生，并随所有者级联删除，判断语义与原规则完全一致（有对比测试）。
- **U10 保留顶栏「退出登录」，删除侧栏按钮**：侧栏在手机宽度下会隐藏，顶栏始终可见。
- **U2 安装令牌仍在提交时立即清空**（沿用现有「秘密不驻留」设计），改为显示「正在验证…」并在失败后把焦点放回输入框。

### 手工验收（评审实例）

- 部署新镜像后，旧库（schema 3）显示「网站需要维护升级」，就绪检查返回 503，符合预期。执行 `npm run db:migrate` 后，结构升级为 4，就绪检查返回 200，没有创建或替换管理员，16 个作品保持不变。
- 后台：
  - 网站设置的字段顺序正确；分组导航、分组说明、媒体缩略图位正常；
  - 作品页有搜索框和取色器；
  - 场景编辑页提示「当前模板没有可编辑的场景文案」；
  - 没有运行包时，预览/发布按钮置灰并显示原因；总览页不显示保存栏；
  - 375px 宽度下没有横向溢出，保存栏高度 54px。
- 在原站内容上修改网站标题 → 保存草稿（修订 1）→ 改回 → 保存（修订 2）。数据库中 16 个作品、序号 0–15、slug 唯一，标题已还原。本次流程中，浏览器控制台没有新增错误。
